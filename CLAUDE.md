# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

- `npm run dev` – Vite dev server
- `npm run build` – `tsc -b` typecheck, then production build to `dist/`
- `npm run lint` – ESLint
- No test runner is configured.

## Architecture

Standalone top-down drift racer (React 19 + Vite + TypeScript) rendered to a fixed 320×200 canvas in 80s Amiga pixel-art style. Extracted from "Pixelpenta", so the engine layer mimics that project's game-host API.

- `src/App.tsx` – owns the `Save` and which screen is showing (menu / career / free race / race). `?track=<id>` (or `daily`) jumps straight into a race; add `&mode=attack` or `&mode=drift` for the other modes. Records each finished race through `withResult` and writes it to `localStorage`.
- `src/ui/` + `src/screens/` – every menu is drawn on a 320x200 canvas with the game's own 3x5 pixel font (Amiga look), not DOM/CSS. `ui/kit.ts` has the primitives (bevelled boxes and buttons, raster bars, starfield, gradient logo, medal chips; palette `C`), `ui/Retro.tsx` hosts a `RetroScreen` object (`draw`, `key`, `hover`, `click`, `wheel`) on a canvas, `ui/nav.ts` maps arrows/WASD/Enter/Space/Esc. Screens: `Menu`, `TrackList` (scrolling grouped list; `Lists.tsx` builds the Career and FreeRace/attack/drift groups from `rows.ts`), `Garage`, `RaceScreen`. `RaceScreen` owns the game canvas and starts a race in an effect; when the race ends it freezes the last frame (`getImageData`) and draws the result panel over it. `createGame` reports the detailed `RaceResult` through a callback just before the host's `onEnd(raw)` fires. Escape leaves a race. Also: `Settings` (sound, volume, weather, time of day, CRT scanlines, on by default, via the `scan` class on `<html>`, export/import/erase save as a base64 code), `Editor`/`EditorList` (below), `ui/map.ts` (`drawMap`: a track's route as a thick line, used for the map in track lists and in the editor), `ui/Crt.tsx` (the frame all canvases sit in, so scanlines line up with source pixels). New characters must exist in `engine/pixelfont.ts` (caps, digits and a few symbols only). Dev shortcuts: `?screen=garage|career|free|settings|editlist|editor`, `?track=<id>&mode=attack|drift`, `&at=<centre-line sample>` (start part-way round, to look at scenery), `&demo=result` (show the result panel).
- **Track editor**: custom tracks live in `localStorage` (`game/custom.ts`, key `driftking.custom.v1`, max 12, validated on load) and are registered with `setCustomTracks` so `allTracks()`/lists/`?track=` see them (ids start `custom-`, grouped as CUSTOM). The editor edits control points on a map (mouse drag/click/right-click, keys in the on-screen help). It runs the same `checkTrack` the generator uses and shows the reason when invalid; only valid tracks can be saved or test-driven (id `custom-test`, leaves no records). Points 0, 1 and the last two are the start straight and keep one line (any direction): dragging point 0 moves the whole straight sideways, the other three only slide along it. `S` makes the selected point the start (`withStart` in `game/custom.ts` rotates the loop and re-lays the straight, trying shorter straights until the track validates). **Road width**: `W` cycles a track-wide level `wd` 0-3 (+4 px per side per step) and `B` sets a per-control-point `bump` 0-3 (+6 px per step, eased between points by `addPointExtra` in `race/track.ts`; not on the start straight) for corners to drift in; both are optional fields on `CustomTrack`, `customToTrack` turns them into `Track.halfWidth`/`pointExtra`, `trackWidths` gives the real half width per sample, and `checkTrack` uses it (`hwOf`) for the road-touches-itself test. The editor map draws the road at its real width. Share codes are `DK1-` with JSON v2 (`w`, `q`); v1 codes still import. **Custom tracks pay no prize money** (otherwise a tiny track could be farmed). `forgetWorld(id)` evicts a cached world when a track is replaced.
- **Weather and time of day** (`race/conditions.ts`, `race/weather.ts`): time of day is purely visual. Rain and snow also cost road grip through `weatherGrip` (rain x0.9, snow x0.86 except on SNOW tracks), passed to physics and AI as `Env.grip`; drift points scale with it too. `conditionsFor(track, settings)`: Auto uses the track's own mood (hand-picked `MOODS` or from its id and environment), otherwise the setting wins. `Weather` draws rain/snow, a dusk tint, and at night a dark mask with banded headlight cones punched out of it (plus glow round boost strips) before the HUD.
- `src/game/` – progression, no React or canvas. `career.ts`: `CUPS` (4 cups × 4 track ids), medal targets (`targets(track)` = multiples of `parTime(track)` from `race/track.ts`, factors in `FACTORS`, **not yet tuned against real laps**), `UNLOCK_POINTS` (bronze 1 / silver 2 / gold 3 per track) to open the next cup, `nextCareerTrack`. `save.ts`: versioned `Save` (v3: `best` = race time/medal per track id, `attack` = time attack best lap + ghost + best per-lap drift + best lap medal, `driftMode` = drift challenge best score/medal, `earned` = money per `mode:trackId`, `money`, `garage` = owned cars / selected / upgrade levels per car) in `localStorage` key `driftking.save.v1` (the key kept its name across migrations; older saves load with defaults for what they lack); `loadSave` discards malformed entries and survives blocked storage. Scores are in 1/100 s everywhere (`format.ts` `fmt`).
  - `cars.ts` (models: price, sprite `look`, stat multipliers; upgrade prices; `statsFor` = model + fitted upgrades → `CarStats`), `garage.ts` (pure buy/select/upgrade ops returning a new `Save` or `null` when not allowed), `economy.ts` (**only career races pay**: `App` zeroes the prize for everything else, and `rowFor(..., career)` marks which list rows pay; the mechanics below still hold for the three modes: `MEDAL_PAY` per mode, bonus only for the step up from the track's best medal; races also pay a place prize for 8 places, repeat runs 40%, plus drift/20; `potential` = what is still on offer, shown in the lists next to what `save.earned` says was earned). `career.ts` also holds lap targets (time attack medals) and drift challenge targets (scale with track length, 90 s limit) — all medal factors are untuned first guesses.
- `src/engine/host.ts` – `startRace()` is a minimal stand-in for Pixelpenta's GameHost. It builds a `GameApi` (see `engine/types.ts`) and passes it to a `CreateGame` function. The api provides canvas/ctx, `input`, `audio`, `setScore`/`setStatus`, `loop(update, draw)` (dt clamped to 50ms, update skipped while paused), `listen` and `onCleanup` (auto-removed on teardown), and `end()` (250ms delay, then `onEnd`). There is no countdown, pause menu or points system in the host. The race handles those itself.
- `src/engine/` also holds `input.ts` (keyboard state), `audio.ts` (a shared singleton `audio`, unlocked on start), `pixelfont.ts`, and `util.ts`.
- `src/race/` – the game, split by concern. `createGame(api, track)` in `race.ts` returns a `GameInstance`.
  - `paint.ts` – all world painting (`paintWorld`): ground as big flat tone patches that meet in narrow dithered seams (the road itself stays flat and clean — Super Cars II style; the user found heavy all-over dithering overkill), curb outline, gravel verge, lane markings, start line + gantry posts, grandstand, cel-shaded props (tree, pine, bush, cactus, rock, buildings with rooftop gear), tyre stacks on corner outsides (collidable), boost strips, puddles/oil, lake. Everything is snapped to the Amiga 12-bit palette (`engine/pal.ts`: `snap`, `quantize`, `ramp`/`bayer` dithering, `band` hard tone bands, seeded `makeNoise`/`hash2`; never use `Math.random` here, painting must be repeatable). Water glints and the gantry bar are animated/drawn by `render.ts` at runtime.
  - `track.ts` – the `Track` type (control points `cp`, world size, laps, road width, `props`, `ground`, `roadGrip`, optional lake, colour `Theme`) and `buildWorld(track)`, which turns it into a `World`: a Catmull-Rom centre line sampled every 4px (`S`, with tangent/normal), per-sample road half-width `hw` (wider in corners) and AI target speed `aiSpd`, a pre-painted bitmap, a `surf` byte map (`GRASS`/`ASPHALT`/`CURB`/`SOLID`/`WATER`) used for collision, trees and a minimap. `getWorld(track)` caches one world per track id for the page lifetime. Also `surfAt`, `nearestIdx` (windowed search, cheap per-frame) and `globalIdx` (full scan, for resets).
  - `tracks.ts` – five environments (`MEADOW`, `DESERT`, `FOREST`, `SNOW`, `CITY`), each bundling theme colours, off-road `ground`, `roadGrip`, prop kind/density, laps and road width, plus the `TRACKS` list and `dailyTrack()` (date-seeded). Tracks are either hand-drawn control points via `fromEnv(...)` or `generated(id, name, env, seed)`. **To add a track, add an entry here**; the App's picker groups by `env`. `?track=<id>` (or `?track=daily`) selects one on load.
  - `trackgen.ts` – seeded generator (`generateCenterline`) for a clockwise loop with a straight along the top. It retries derived seeds until `validate` passes: inside the world, far-apart road never closer than road width, no hairpin sharper than 1.75 rad per 72px, a minimum number of real corners, and a straight ~100px each side of the start line (the grid). Same seed gives the same track everywhere. Seeds that fail validation after 600 attempts throw at module load.
  - `car.ts` – `Car` (with `stats: CarStats`, multipliers that `drive` applies to grip, acceleration, top speed, slide readiness and braking; AI cars use `UNIT_STATS`), sprite sets (`getLooks`: looks 0-5 are the player's cars in `CAR_MODELS` order, 6-8 the AI's; 64 rotation frames each plus shadows), `createGrid`, player physics `drive` (off-road behaviour comes from the `GROUNDS` table by `track.ground`; `track.roadGrip` scales on-road grip), `moveCar` (walls/trees) and `collideCars`. Hits are reported through the `Env` hooks (`bump`, `treeHit`), so physics never touches race state.
  - `ai.ts` – `FIELD` roster and `aiDrive`: lane-wandering pursuit of the centre line shaped by a `Persona` (aggressive drivers move over to cars alongside, cautious ones give way and brake, brave ones keep corner speed, drifters allow slide), everyone keeps a gap to the car ahead (without it cars pile up and `collideCars`' position correction gives free speed), weak rubber band (±3-4%). A finished player is switched to `ai` with no persona so the car coasts to a stop.
  - `render.ts` – `createRenderer(ctx, world)` owns a private copy of the track bitmap (skid marks are painted onto it) and draws world, particles, cars, minimap and the HUD (time/lap/position/best lap, speedometer, drift score) from a `View`. Also exports `SW`/`SH` (320×200).
  - `ghost.ts` – time attack ghosts: a lap is a flat integer list of x, y, sprite-frame triples at 20 Hz (`LapRecorder`, `ghostAt`), and `ghostTimeline` turns it into time-per-centre-line-sample so the live gap to the ghost is `lapClock - timeline[player.idx]`.
  - `race.ts` – `createGame(api, track, { car, onResult, attack, drift })`. The field is 8 cars (`FIELD` in ai.ts, 7 AI personas + the player; time attack and drift challenge drive solo). Boost strips and hazards (puddles = less grip, oil = almost none) are placed by `buildWorld` deterministically from the track shape/id, so no track data lists them. Draft = slipstream behind a car ahead. `drift` option = drift challenge: timed, score is banked drift points, ends with `finishDrift`. With `attack` the player drives alone with no finish: laps are timed from the start line (the first crossing starts lap 1; the grid-to-line run is an "out lap"), the best lap's ghost replays, and a lap counts only if the car was not reset (off track/water) or reversed over the line. Drift points are scaled by `roadGrip^1.5` so slippery tracks pay less. Orchestration: lap/position tracking, off-track recovery, drift-chain scoring (final raw score is time minus drift bonus, in 1/100 s), engine sound, camera.

Controls: arrows/WASD to steer, Space for the handbrake.

## Balance, font and music (read before tuning)

- **Calibration**: `tools/bot.ts`, `tools/aisim.ts`, `tools/driftbot.ts` drive the real physics headlessly (see their headers for how to run). Findings that set the numbers: the baseline AI profile is ~35% slower than a bot can drive, so `AI_PACE` (race/ai.ts) is 1.25 for Normal (`DIFFICULTY` in game/settings.ts scales it: easy .9, hard 1.08, and prize money .7/1/1.3); medal factors in `game/career.ts` are fitted to bot laps (bronze ~1.2x the profile, silver ~1.4x, gold ~1.55x); drift targets scale with track length and `roadGrip^3`. AI cars get more forgiving grip than the player, so never judge AI pace by the profile alone. A reset (off track/water) costs +2 s in races and drift challenges.
- **Font** (`engine/pixelfont.ts`): 5x7, anti-aliased by smoothing each glyph bitmap with Scale2x then averaging back to 25/50/75/100% ink pixels; `small: true` selects the old 3x5 for tight spots. Text advance is 6 px, height 7 px.
- **Music**: real ProTracker modules in `public/music`, listed in `SONGS` (engine/music.ts: id = file name, title, artist or '' when the file doesn't name one, and a `gain`). `engine/mod.ts` has `parseMod` and `ModPlayer`, which renders a module a block at a time (Paula-style mixing, A500 low-pass, sample finetune, and effects 0-4, 9, A, B, C, D, F plus E1 E2 E6 E9 EA EB EC ED EE; not implemented: 5/6/7, pan, waveform/filter commands, so add those if a new song needs them). `engine/music.ts` streams it: four-second blocks queued ~12 s ahead on the audio clock (gapless, a few MB of memory even for a ten-minute song), and a playlist that moves on when a song ends. To add a song: drop the .mod in `public/music`, then add a `SONGS` entry; measure `gain` with `renderMod` at a low gain as the comment in music.ts describes (equal RMS, capped so the peak stays under 0.95). The main menu credits whichever song is playing. The stream only begins once the audio context is really running (`audio.whenRunning`, since browsers keep it suspended until a gesture); `App` retries the unlock on every kind of gesture until it runs. Settings has SOUND, MUSIC (also the M key), SONG (all songs or one) and VOLUME; `App` calls `music.configure(on, song)`.

- **Settings persistence**: `game/settings.ts` saves every change to `localStorage` (`driftking.settings.v1`, written by an effect in `App`) and reads it back on start, field by field, so one bad value never resets the rest. The stored object carries a `v` version; settings written before version 2 (when scanlines defaulted off automatically) take the new scanline default but keep everything else. Bump `VERSION` the same way if a default ever needs to override old saves.

## Career, replay, sharing and input (added later)

- **Career difficulty**: `careerPace(trackId)` in `game/career.ts` scales the AI pace from 0.92 (first track) to 1.11 (last), and `careerPrize` raises prize money by 15% per cup; `App` multiplies both onto the difficulty setting. Non-career tracks get 1. Medal targets use `TUNE`, a per-track correction on the par time measured with `tools/medalcheck.ts` (run it again after any physics change: the bot's bronze and silver laps should land at ~100% of the lap targets on every track).
- **Replay** (`race/replay.ts`): `ReplayRecorder` stores every car's x, y, angle at 20 Hz during a race or drift challenge (not time attack) and `RaceResult.replay` carries it to the result panel. `createReplay` plays it with cinema bars (`View.cinema`) and three camera types. The result panel's buttons are clickable (RETRY / REPLAY / NEXT / MENU).
- **Start sequence and finish**: `race.ts` holds everyone on the grid for `COUNT` frames while three lamps light (`View.lights`); the chequered flag sweeps in after a finish (`View.flag`); `View.shake` shakes the camera on hits.
- **Track sharing**: `exportTrack`/`importTrack` in `game/custom.ts` (code `DK1-` + base64 JSON), used by the SHARE/IMPORT buttons in `EditorList`. Imports are validated with `checkTrack`.
- **Gamepad and touch**: `engine/gamepad.ts` (`readPad` is read by `Input` in a race; `startPadMenu` turns the pad into key events for the menus when no race has its `Input` attached). `ui/TouchPad.tsx` shows driving buttons on coarse-pointer devices; it sends the same key events as a keyboard.

## Online duel (two players, added later)

PLAY ONLINE in the main menu (`screens/Online.tsx`): a race for two humans (no AI), with no server of our own and no accounts.

- **Pairing and transport** (`net/relay.ts`, `net/mqtt.ts`, `net/connect.ts`, `net/link.ts`): the host picks a track, gets a six character room code (first character = which broker, then five from an alphabet without 0/O/1/I) and chooses the number of laps (sent to the guest in `hello`, `Session.laps`); the friend chooses JOIN and types the code (a `window.prompt`). Both connect to a free public MQTT broker over a WebSocket (`BROKERS` in relay.ts; HiveMQ first, EMQX only if HiveMQ is unreachable because EMQX's public broker drops most messages at game rates; `mqtt.ts` is a hand-written MQTT 3.1.1 client, QoS 0) and meet on topics `driftking/v1/<code>/h` and `/g`. The guest knocks (`hi`) until the host answers (`ack`); both send a `hb` heartbeat every 2 s and treat 8 s of silence as a lost link. That relay link is then upgraded (`connect.ts`): the offer/answer of a direct WebRTC connection travel over the relay (`rtc`, `rtc-answer`), both sides wait up to 6 s for the channels to open, the host says which path to use (`path`), and if direct works the relay is closed; otherwise the game simply carries on over the relay (`sendFast` drops snapshots when the WebSocket's buffer is behind). Direct WebRTC (`link.ts`: STUN only, no TURN, so strict NATs fall back to the relay) has two negotiated data channels, `ctl` (reliable, inputs and events) and `state` (unordered, no retransmits, snapshots). `Link` is the transport-neutral interface the game uses; `loopback(delay, loss, jitter)` is an in-memory pair for tests. After the final link is up the guest sends `join {look}` and the host answers `hello {trackId, cond, looks, laps}`; both then call `onStart` and `App` shows a `RaceScreen` with a `Session` (`net/session.ts`). A first version swapped two long WebRTC codes by hand; it failed on many routers and was replaced.
- **Sync** (`net/duel.ts`, the `online` option of `createGame`): host-authoritative. The guest sends its inputs in small batches (`{k, dt, steer, gas, brake, hand}` per frame, rounded, and the guest steps with the same rounded numbers); the host plays them back at the pace they were made rather than as they arrive (`credit` in race.ts) and steps the guest's car once per tick, so both sides run the same `drive` on the same sequence. The host sends a snapshot of both cars ~30 times a second with `k` = last guest tick stepped and `ts` = host clock. The guest predicts its own car and remembers its pose per tick (`PoseHistory`); when a snapshot arrives the car is moved to the host's pose for tick `k` at once and the difference goes into `corr`, a drawn-position offset that fades in ~70 ms, so corrections glide instead of popping. The host's car is drawn on the guest from a timeline of the snapshots' own timestamps (`Interp`: delay 70-300 ms that follows the connection's jitter), so arrival jitter doesn't show; the guest's car on the host is smoothed (`vis`). Collisions are detected on both sides, the host's result wins. Host-only: lap counting, finish order, lights (`go` flag), a 25 s limit for the loser after the winner crosses (`DNF_AFTER`). The guest takes laps/position from snapshots and the finish from a `fin` message. Both drive the stock car (`UNIT_STATS`); the look comes from each garage. Weather comes from the host's settings.
- **Differences from a normal race**: no AI, no replay, no prize money or records, no +2 s reset penalty (a reset just puts the car back), result by crossing order, `RaceResult.place` 0 = connection lost. The result panel offers REMATCH (both must ask; `RaceScreen` bumps `run`, which is also the `rid` on every message) and MENU. Leaving a race closes the link (`bye`), and the other side gets `CONNECTION LOST` / `OPPONENT LEFT`.
- **Known limits**: the guest starts about one round trip behind the host (lights go green by snapshot, inputs travel back); a collision shows a small correction on the guest. `GameInstance.inspect()` exposes the race state for tests. WebRTC cannot be tested in the Claude sandbox (UDP is blocked), but the broker relay can: two headless browsers against the real brokers worked. Test the sync alone with `loopback` and two `startRace` canvases driven by bots.
